# ATAK — rafale de 503 sur toutes les lectures

## Contexte

Console du poste de commandement : `explosive-timers`, `pings`, `medical-alerts`,
`cas`, `recon/images`, `map-shapes`, `intel/photos`, `perstat`, `activity`,
`weather`, `chat`, `video-feeds`, `device-alerts`, `laser-codes`, `stats`
répondent tous **503**. La page `/atak` elle-même s’affiche.

## Symptôme

La carte s’ouvre, puis plus aucune donnée ne se met à jour (charges, pings,
alertes, photos, météo…). La console se remplit de 503. Un 404 `/favicon.ico`
et des `runtime.lastError` d’extension navigateur apparaissent à côté, sans
rapport.

## Cause

Ce n’est pas un endpoint ATAK cassé : **toutes** les lectures tombent ensemble.
Le worker PHP n’atteint plus MySQL (`database_unavailable`, souvent
`SQLSTATE[HY000] [2002]` sur l’hébergeur). La page HTML a pu se charger
juste avant, puis la rafale de polls (toutes les 3 s, plus les timers
médecin / ordres / activité) aggrave la panne.

Hors sujet dans la même console :

- images en chargement différé : avertissement Edge/Chrome, pas une erreur métier
- `runtime.lastError` : extension navigateur
- `/favicon.ico` : l’ATAK n’avait pas d’icône déclarée

## Correctif

- Pause des lectures GET `/api/*` après un 503 (Retry-After, ~30 s) pour
  arrêter de marteler la base
- Message unique côté carte + pastille hors liaison
- Lectures pings / charges : liste vide plutôt qu’une exception non gérée
- Icône Athena déclarée sur la page ATAK

## Fichiers touchés

- `public/assets/js/atak-socket.js`
- `views/atak.php`
- `app/Controllers/Api/AtakApiController.php`

## Vérification

Contrôle du code. Recette : ouvrir `/atak` ; si la base est coupée, un seul
message puis silence réseau pendant la pause ; dès que MySQL répond, les
polls reprennent. Le 404 favicon disparaît si `assets/icons/athena-192.png`
est bien déployé.

## Statut

Corrigé (sources) — la base hébergeur reste à rétablir si les 503 continuent
après déploiement
