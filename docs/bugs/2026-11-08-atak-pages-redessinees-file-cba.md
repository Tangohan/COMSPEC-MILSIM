# Apps ATAK : une action simple redessine la page, une erreur de bouton se rejoue à chaque image

- **Contexte** : même retour partenaire : accrocher un flux de drone, cliquer le haut-parleur, envoyer un message, charger un lien de diapositives, changer un réglage, lancer une chanson : « tout rafraîchit la page et relance l'app » ; sur les cartes lourdes le rafraîchissement échoue. Ils ont aussi perdu le téléphone et l'Arsenal ACE.
- **Symptôme** : page entièrement recréée à chaque action simple ; après une erreur de script dans un bouton, le téléphone et ACE ne répondent plus.
- **Cause (redessin)** : ces actions appellent `pageRender` au lieu de mettre à jour une ligne (`fn_formSet`).
- **Cause (perte du téléphone et d'ACE)** : mécanisme **confirmé par lecture du code de CBA 3.19.0** (`cba_common.pbo`, `init_perFrameHandler.sqf`), pas encore vu en jeu. `CBA_fnc_onFrame` exécute `{ (_x select 0) call (_x select 1) } forEach nextFrameBufferA`, puis seulement après, échange `nextFrameBufferA = nextFrameBufferB`, vide B et met à jour `nextFrameNo`, puis traite `waitUntilAndExecArray`. Une erreur de script dans un rappel interrompt tout le gestionnaire : le tampon A n'est jamais remplacé, donc le même rappel (et ceux qui le précèdent) est rejoué à chaque image, et tout ce qui suit (autres rappels de la file image suivante dont ceux d'ACE, `waitUntilAndExecute`) ne s'exécute plus. C'est le cas du `call _sonNow` sans argument corrigé dans cette PR (clic envoyé par `_click` de `fn_formRender` via `CBA_fnc_execNextFrame`).
- **Correctif** : `_click` (`fn_formRender`) et `fn_clickNext` n'exécutent leur rappel qu'une fois (drapeau posé avant l'appel) : une erreur coûte une image, la file se vide à l'image suivante. Mises à jour sur place : Musique (lancer, sauter, passer, arrêter, avancer, fin de piste ; piste en cours teintée dans les listes ATHENA, FICHIERS, SERVEUR, LIEN ; la page LECTEUR n'est redessinée que si la file ou les favoris sont dépliés), Réglages (14 interrupteurs du profil sans effet sur la mise en page, étiquettes `map_show_*`), Drone (VISION JOUR / NUIT / THERMIQUE). `fn_formSet` gère aussi `person` et `btn`.

- **Converti ensuite (2e lot, à vérifier en jeu)** : Messages : message envoyé ou reçu au canal, conversation ouverte : seul le fil est refait (`[true] call fn_pageChat`, en-tête seulement calculé, saisie et focus intacts). Réglages : `fn_formSet` « segment », 15 choix exclusifs lus au prochain dessin et les styles CBA de la carte. Musique : FAV change sur place hors de la page LECTEUR. Diapositives : « et » mettent à jour la ligne de l'écran (`fn_briefingAction` « castLine », « castRefresh »). Drone : VIDÉO DU DRONE / DU TÉLÉPHONE sur place dans la vue caméra (`feedNext`).
- **Converti ensuite (3e lot, à vérifier en jeu)** : file Musique dépliée : MONTER et RETIRER réécrivent les lignes sur place (`fn_musicAction` « qRow », `fn_formSet` « person » avec boutons, ligne masquée si elle est en trop). Liste des conversations, SMS du contact déjà en tête : `fn_chatListRow`. Diapositive Athena dont Arma accepte l'image : image posée sur place (`COMSPEC_ATAK_SlideWait`).
- **Converti ensuite (4e lot, à vérifier en jeu)** :
  - File Musique : VIDER LA FILE, dernier retrait, saut et arrêt, file dépliée : lignes réécrites sur place, bouton VIDER masqué sous 2 morceaux, message de file vide sur la première ligne. Une ligne masquée laisse sa place jusqu'au prochain redessin.
  - Liste des conversations : SMS de n'importe quel contact listé : sa ligne remonte en tête, les autres descendent d'un rang (`fn_chatListRow`, contrôles de chaque ligne notés par `fn_pageChat`).
  - Diapositive : navigateur intégré (Athena et Google) et message d'erreur posés sur place (`fn_slideWaitDone`). C'est le cas courant : sans `-filePatching`, Arma refuse les images téléchargées.
  - Vidéo Live : **cause du « relance l'app » : `fn_pageClear` appelle `fn_livecamStop` à chaque rendu, donc tout redessin détruisait la caméra.** Vision, palier, source du même genre (porteur, caméra fixe, drone) et RENOMMER passent par `fn_livecamLive`, sans détruire la caméra. Changement de palier : rendu coupé, texture changée, rendu repris, comme le faisait le redessin.
  - Drone, vue caméra : MONTER, DESCENDRE, CAMÉRA VERS LE SOL sur place.
- **Laissé en redessin, avec la raison** :
  - Drone, `cam` (ouvrir et fermer la caméra) : la page change entièrement de disposition (télémétrie, image, barre groupée à la place des onglets). Rien n'est perdu au redessin : la caméra du drone n'est pas détruite par `fn_pageClear`, contrairement à Vidéo Live. Préparer la vue à l'avance serait un risque sur un flux testable en jeu seulement. Restent aussi redessinés : MARQUER (cadre et réticule), NETTETÉ (la caméra est recréée), MENUS, RÉGLAGES.
  - File Musique : file de plus de 40 morceaux (plafond d'affichage), ajout d'un morceau (la page n'a pas la ligne).
  - Liste des conversations : contact pas encore listé ; choix d'un destinataire en cours.
  - Diapositive : ACTUALISER ; FENRIR ; navigateur intégré indisponible.
  - Vidéo Live : changement de genre de source (les boutons sur l'image diffèrent), retour de liaison, panneau PARTAGER (pas d'image à garder : le panneau la remplace).
  - Réglages à effet de mise en page (thème, coque, luminosité, taille du texte) : redessin voulu.
