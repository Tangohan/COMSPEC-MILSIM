# Session Athena « prête » puis 401 sur toutes les transmissions

## Contexte

11 septembre 2026. Overwatch 1.5.16 + liaison 2.0.17. Connexion Steam / restauration de session : le journal annonce « Session Athena prête », puis chaque envoi (fiche opérateur, chat, position, manifeste, scène) est refusé.

## Symptôme

- Handshake `ok=true` / `Session Athena prête`
- Boucle `ÉCHEC · fiche opérateur — unauthorized`
- HTTP 401 sur `/public/api/chat`, `/public/api/atak/position`, `flight-manifest`, `scene/ingest`
- Indicatif BFT reste le groupId Arma (`ALPHA 2-3`)
- Encart carte (indicatif, nom, groupe, fonction) vide
- Tuile Connexion Athena sans accès clair au code « Lier le jeu »

## Cause

Deux défauts combinés :

1. **Priorité d’auth** : l’extension envoyait `X-COMSPEC-KEY` (souvent une ancienne clé CBA/profil) **et** un Bearer de session jeu. Le portail lisait d’abord la clé header et refusait sans examiner le jeton jeu.
2. **READY trompeur** : après Game Auth, `FinishGameAuthReady` posait `READY` même si `client-init` échouait (`C2_DEGRADED`). Le SQF démarrait les boucles de sync et martelait des endpoints protégés. De plus, le reauth après 401 n’existait qu’en mode clé communauté.

Conséquence identité : sans canal C2 valide, le bootstrap / avatar n’alimente pas correctement le poste ; le BFT retombe sur le groupId Arma et l’encart reste vide.

## Correctif

- PHP : essayer **tous** les secrets présentés (clé header, Bearer, JSON) jusqu’à un accepté.
- Extension : avec un jeton jeu, ne plus envoyer une `X-COMSPEC-KEY` non validée ; rafraîchir le Bearer avant envoi ; reauth après 401 aussi en mode jeu-seul ; ne plus laisser `Connect` async écraser une session jeu avec une clé vide.
- Tokens PHP : `expires_in` exposé pour le refresh proactif.
- SQF : `isC2Ok` — READY + erreur C2 ≠ transmissions ; journal clair si compte lié mais canal coupé.
- UI : bouton **Lier le jeu (code du portail)** depuis Connexion Athena.
